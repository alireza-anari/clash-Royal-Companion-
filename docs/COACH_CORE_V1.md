# CRC Coach Core — phase 1

- Online only; preserve existing chat, loader, API gates, quotas and deployment.
- Readable Persian by default; concise actionable answers; adapt to user language and skill. Use visual elements only when helpful. Never invent statistics, card ownership, active forms, meta, or replay observations.
- UI v1: render plain-text headings and bullets safely; optional catalog images for explicitly mentioned card names (not recommendations or proof of ownership). Maximum four. No external model-provided URLs or HTML.
- Current private beta edge routes coach chat to LEGACY_LIVE, not FastAPI. The active inference source must be verified before changing prompts or routing. Do not deploy or alter activation flags in this PR.
- Future: versioned server-side identity, evidence schema, tool orchestration, response validation, structured outputs, RAG, isolated per-user memory (requires distinct authenticated identities), meta/events, training, vision and fine-tuning. Keep provider and data collection policies intact.

## Phase 1, slice 2
- Page-local conversation retains two successful turns, scoped to the loaded profile object; clearing chat, reloading the account, or refreshing the page resets it. Only free chat sends optional history, with explicit tag/email masking and 4096-byte budget; no durable storage. The UI discloses free-text history transmission. Account change during inference discards the old reply.
- Current evidence stays ahead of history; invalid aggregate counts are omitted. Leaked elixir is reported separately for observed wins and losses; no causal claims.
- `coach-core-v1.mjs` is a review-only worker patch combining identity, intent hints, deterministic aggregate validation and token budget selection. It preserves free-text questions, existing guided tasks, quotas and model provider. A single verified live model is available, so multi-model routing is not enabled. The free-text answer remains unverified semantically; typed recommendation validation and long-term memory are later work.

## Phase 1, slice 3 — source-backed coaching
- Added a compact, versioned lexical RAG corpus with five curated Supercell Support sources verified 2026-11-26: Cards & Decks, 1v1 Battle, Card Evolution, November 2026 feature notes, and October 2026 feature notes. Every retrieved chunk carries a source URL, authority, verification date and freshness class.
- Retrieval normalizes Persian/Arabic characters, expands common Persian/English game terms, uses question + selected card names + guided action, ranks a maximum of three chunks, and injects them as untrusted reference data. The prompt requires source IDs for factual mechanics and prohibits using this corpus to claim current meta, win rates, or live event availability.
- Worker responses carry source metadata; the browser validates Supercell host/path allowlists and renders official references as safe external links. Invalid model citations are removed and missing citations are backfilled with retrieved IDs.
- This is a lightweight local lexical RAG MVP, not vector search and not a live news crawler. It adds no Cloudflare service or provider. The corpus requires reviewed updates; future AI Search/Vectorize remains an optional scale step after freshness and cost needs justify it.

- Retrieval tuning: Persian event/news/ability synonyms are expanded; event intent prioritizes dated official news chunks. Electro-specific source chunks require an Electro/Wizard query token, preventing a generic Giant Evolution question from retrieving the Electro Giant article. `meta` is a distinct intent and does not fall through to events.

## Phase 1, slice 4 — deterministic response quality
- The model is asked for strict JSON: answer, swap_index, fact_keys, source_ids. No provider-specific JSON mode or additional inference request is needed. Invalid schema, unavailable fact keys, invalid swap indices and unknown source IDs fail closed with a clearly labelled limited response after an online model call.
- Detected suggestion intent displays only a server-rendered approved single swap, with role gains/losses, cost/level tradeoffs and a caveat about unverified ownership. Statistics are calculated from submitted aggregate evidence, not generated by the model. Meta and replay intents explicitly report unavailable live/replay evidence.
- Only model-selected retrieved source IDs are returned; no citations are automatically attributed to unsupported prose. The quality status means structure/selected evidence checks, NOT semantic correctness, authenticated account ownership, or a prediction of win rate. Free prose can still be wrong and needs evaluation against human-reviewed examples. No extra inference calls or services, no offline coach, no deployment.
- Unit tests cover adversarial outputs, inconsistent counts, protected forms, invalid swaps, unknown source IDs, missing meta/replay evidence. The existing composed patch syntax test remains a release gate. Human evaluation and user-feedback persistence are separate future work.

- A conservative Persian/English lexical screen withholds model-written numerical win-rate claims; the server's own calculated results remain available. This is not a full semantic validator. The client recognizes versioned limited-response metadata without advertising unchecked prose as verified truth.

## Phase 1, slice 5 — model router
- Added a fail-closed Workers AI router. The verified default remains `@cf/google/gemma-4-26b-a4b-it` for deck, coaching, evidence and all complex requests. An optional fast route accepts only `@cf/zai-org/glm-4.7-flash` via the `COACH_FAST_MODEL` environment binding and only for exact trivial greetings/thanks; it is not activated by this change because the second model has not yet passed a Persian structured-output benchmark.
- When the optional fast route is explicitly configured, upstream failure or a limited response caused by invalid JSON/schema/unknown fact/source triggers at most one retry on the existing Gemma model. Semantic uncertainty and unsupported numerical win-rate claims do not trigger retries. The response includes the selected model, route, fallback flag and router version.
- No arbitrary model ID can be injected by a request or environment value. No extra inference calls occur on the default route. A future benchmark must compare Persian structured-output validity, latency, quality and measured token usage before enabling `COACH_FAST_MODEL`.
- Cloudflare's published prices as of 2026-11-26 list Gemma 4 26B at $0.10/M input and $0.30/M output tokens, and GLM-4.7 Flash at $0.06/M input and $0.40/M output tokens. GLM is not universally cheaper because output tokens cost more; restricting it to short messages is intentional. Pricing can change.

## Phase 1, slice 6 — coach evaluation lab
- Added 60 synthetic Persian scenarios: 20 deck/cards, 10 battle evidence, 10 allowlisted single swaps, 10 Evolution/Hero, and 10 meta/events. Fixtures contain no real player tags, credentials, or account records.
- Added deterministic scoring on the same JSON schema and response-quality gate used by the coach: schema/quality gate (25), fact-key selection (12), safe swap selection (13), source attribution (15), required content (15), forbidden claims (10), abstention (5), and language (5). This is a reproducible rubric, not a semantic LLM judge; a human should review rubric coverage before treating scores as truth.
- Added a validation-only default CLI and an explicitly billable live mode. Live mode compares only the two fixed Workers AI model IDs, uses synthetic cases, sequential requests, a 220-token output cap, a fixed seed/temperature, a $0.10 estimated-cost ceiling, no automatic retries, and writes a JSON report. It requires \`--live --confirm-billable\`, \`COACH_EVAL_ACCOUNT_ID\`, and \`CLOUDFLARE_API_TOKEN\`; no secret is committed or placed in CI.
- CI runs only dataset validation and offline unit tests. It never calls model APIs. Live benchmark results must be generated separately and include measured usage when the provider returns it; otherwise cost is marked estimated, not actual.
- Pricing inputs follow Cloudflare's Workers AI pricing page last updated 2026-10-20: Gemma 4 26B at $0.10/M input and $0.30/M output; GLM-4.7 Flash at $0.060/M input and $0.40/M output. Workers AI free allocation is 10,000 Neurons/day; usage beyond it on Workers Paid is billed at $0.011/1,000 Neurons. Actual charges depend on measured Neurons, not this token-price estimate.
- No production Worker, routing binding, quota, account secret, or deployment was changed.

- Added a server-side UNVERIFIED_PERSONAL_STATS_IN_PROSE gate. It withholds model-written battle counts, wins/losses, and numeric averages so personal statistics are displayed only from server-computed evidence. The detector deliberately does not block ordinary card elixir costs or four-card cycle mechanics.
- The router requests provider JSON-object output mode, and the evaluation prompt supplies case-specific allowed fact keys, source IDs, and safe swap indices.
- Final live benchmark results are recorded in docs/COACH_EVAL_REPORT_2026-11-26.md. Gemma remains the recommended substantive coach model; GLM is not enabled as a general fallback.
