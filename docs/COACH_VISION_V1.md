# Vision Intelligence — stage 12, capture foundation

## Actual implementation
Explicit in-app capture dialog, supported secure desktop browsers only. Browser permission picker must report a single window or tab; reject entire screen, unknown surface and audio tracks. getDisplayMedia from a direct click, no microphone/camera, no persistent permission, no native game automation. Sample video locally via canvas ImageData, max 320 pixels on longer side, 2-second target interval (browser throttling may drop samples), 240-second elapsed-time limit checked on sampling, 120 frames and 24 MiB image buffer. No full video, upload, storage, model inference or gameplay detection. Stop releases tracks; review local frames only after stopping; discard/close/navigation/profile change/pagehide clears buffers and stops sharing. A pending permission response after cancellation is released. Browser system sharing UI remains authoritative. Timers may be suspended in the background; stop at OS sharing control if the browser is suspended. No capture on mobile claimed. The capture dialog does not alter the online coach consent or chat flow. CSP permits local media only (self/blob); Permissions-Policy permits display capture on same origin, denies microphone/camera. No external network destinations added.

## Platform constraints (reviewed 2026-11-26)
- Web: https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getDisplayMedia — secure context and fresh user action/permission, browser controls source. Cannot silently start or guarantee cross-app capture on Android/iOS.
- Android: https://developer.android.com/media/grow/media-projection — native app + MediaProjection foreground service, consent per session, Android 14+ one-shot projection, system stop callback. Candidate for first native companion; record only game surface if supported. Native implementation not included.
- iOS: https://support.apple.com/en-gb/guide/security/seca5fc039dd/web — ReplayKit consent and system broadcast extensions; native app/extension, explicit broadcast start and OS constraints. Test on actual device and App Store review before promising capability.
- https://supercell.com/en/fan-content-policy/ and https://supercell.com/en/safe-and-fair-play/ — gameplay footage/coaching is not blanket approval of every implementation or monetization. No client modification, input injection, bots, live overlays or in-match tactical advice. Review rights, privacy and applicable store policies before publishing paid capture/analysis.

## Observation contract and remaining work
Strict local validator permits only unverified card-visible, unit-visible (normalized image coordinates), or elixir-visible observation tied to an actual captured frame timestamp and allowlisted card ID; never treats this as game-clock or confirmed card deployment. Reject unknown kinds, fields, confidence claims and invalid timestamps. No detector feeds this contract yet. Sparse downscaled samples cannot establish continuous actions, exact elixir use or causes of losses. No fabricated analysis.

Next implement native Android consent flow then iOS feasibility, longer/more suitable capture with explicit retention and redaction, verified ground-truth labeled footage, battle boundary/game clock detection, temporal tracking and multimodal evaluation. Server vision endpoint needs separate authenticated upload consent, content validation, encryption, expiration/deletion, per-user limits, model budget and reserved analysis credit/idempotency. Subscription may include a bounded number of analyses and optional separate packages, but billing stays off until actual cost and quality are measured. No model selected/activated here; no real account or video uploaded. Production untouched. Mock tests are not real-device capture validation.
